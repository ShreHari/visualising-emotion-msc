\chapter{Methodology}

\section{Overview and design principles}
\label{sec:method-overview}

Three principles run through the design, and each can be traced either to a decision taken in supervision or to something the data forced.

The first is similarity rather than matching. Two readers each return a distribution over the same seven emotion families, and the comparison between them is a ladder of four measures that reward closeness to different degrees, from a continuous distance on the circumplex to an exact top-1 match (Section~\ref{sec:method-measures}). No measure is treated as the score; the ladder is the result.

The second is that every number is read against its own chance level. This was not a principle I started with. It came from noticing, while building the demonstrator, that two records paired at random already score about \FullNeuVaNull{} on the loosest measure, because most families sit close together on the circumplex and the measure has a floor of 0.41. A bare value of 0.71 therefore looks like a pass and is below chance. From that point on, every subset and every measure carries a random-pairing null (Section~\ref{sec:method-null}), every rate carries a clustered confidence interval, and the two contrasts the design is built around are tested formally (Section~\ref{sec:method-inference}).

The third is describe, do not ask. The vision model is never asked what emotion a drawing shows. It answers five factual questions, the answers are composed into one neutral sentence, and a separate text model infers the emotion from that sentence (Section~\ref{sec:method-pipeline}). The intent is that both sides of the comparison are text read by text models. How much separation this actually buys is not assumed; it is measured by the leak audit and the template ablation in Section~\ref{sec:method-analyses}. Figure~\ref{fig:pipeline} is the map of the chapter.

\section{The corpus}
\label{sec:method-corpus}

The corpus is \nTotal{} records, each a prompt string, a PNG image and an embedded file timestamp. It was collected at the Festival of the Mind in Sheffield between 19 and 29 September 2024. Visitors were invited to describe how they were feeling; the interface accepted any text; each submission produced one drawing. The drawings are 1024 by 1024 pixels and uniformly monochrome, so a line-art style instruction was appended to every prompt by the installation software, and that instruction is not in the data I was given. The provenance manifest embedded in each image names the generator as DALL$\cdot$E without a version and records neither a seed nor the rewritten prompt that the model is known to construct internally \cite{betker2023improving}, so exact regeneration is impossible and the generation parameters are unknown.

The prompts are short. The median is four words, the mean six, and 293 entries are a single word. About 78\% of them are typed entirely in lower case, which matters for name detection later. A few are in Italian, French or German. Records are not linked to individuals: \nRepeats{} of the \nAnalysed{} analysed records repeat a prompt that appears earlier in the corpus, the largest group being the word ``happy'', which was drawn \nHappy{} times; the number of contributors is unknown and can be no larger than \nDistinct{}. Figure~\ref{fig:dataset} shows the composition after pre-processing.

\section{Data pre-processing}
\label{sec:method-preprocessing}

\subsection{Loading and pre-test removal}

The image files follow three incompatible naming patterns (zero-padded, unpadded and prefixed), and two are stored with a lower-case extension that a case-sensitive file system treats as a different file. A na\"ive loader resolves under a fifth of the corpus. The loader in \texttt{emoviz/data.py} handles all three patterns, asserts that exactly \nTotal{} records resolve, and reads the signing time embedded in each image's provenance manifest, which the data as supplied did not expose. Those timestamps show that records 1 to 13 were created between 26 August and 18 September 2024, before the festival opened, scattered across days in a way consistent with developer testing. They are excluded from analysis but still processed by the pipeline, so that the completion figure reported later covers all \nTotal{} images and nothing is silently dropped.

\subsection{Prompt groups}

Every record carries an integer group key computed from its original prompt text, stripped of surrounding whitespace and case-folded, before any redaction is applied. Computing the key before redaction matters: two different people's names both become the same placeholder, and a key computed afterwards would merge two distinct prompts into one group, which happened once during development and was caught by the accounting tests. There are \nDistinct{} groups; \nGroups{} of them hold two or more records, covering \nGroupRecords{} records, and \nPairGroups{} of those groups are pairs. Every confidence interval and every permutation test in Section~\ref{sec:method-inference} resamples or permutes at the level of this key, because records that share a prompt are not independent evidence about the readers. The key is case-insensitive while the prompt reader saw the text as typed, so a handful of groups mix readings (``Ok'' and ``ok'' fall in one group but were read separately); this changes no count and is reported for completeness.

\subsection{Name redaction}

The corpus contains the names of a small number of private individuals, typed by visitors who wrote about a friend, a relative or a teacher. Following my supervisor's direction, these are treated as a data pre-processing matter: names of private individuals are replaced by a placeholder, while content about illness, grief and personal difficulty is kept, because it is not identifying on its own and is essential to the analysis. Redaction happens at load time and the files on disk are never modified, so the analysis, the figures and the demonstrator all see the same redacted text and cannot diverge.

The procedure has three documented stages. Detection is tuned for recall, because with most prompts in lower case capitalisation alone would miss most names: candidates come from the NLTK gazetteer of 7,944 given names \cite{bird2009natural}, from mid-sentence capitalised tokens absent from a 236,000-word English dictionary, and from naming phrases such as ``called X'' and ``my friend X''. Review records a decision for every candidate, keep or redact, with a reason, and scopes each redaction to the record it was reviewed in, which is what stops ``Jack Frost'' and ``woolly mammoth'' being scrubbed as people; the audit fails if any candidate is unreviewed or if a redaction entry no longer matches anything. Application replaces the token per record and collapses consecutive placeholders to one. Eight records are affected. Re-reading the redacted prompts with the prompt reader moves no family probability by more than 0.012 and changes no top-1 family, so the prompt-side labels are unaffected; two records consisted of a name alone and reduce to the bare placeholder, and the control audit in Section~\ref{sec:method-analyses} checks that they change nothing. The decision table itself names the tokens it removes, so it travels with the dataset rather than with the code.

\section{The pipeline}
\label{sec:method-pipeline}

\subsection{Prompt reader}

The prompt reader is a RoBERTa model fine-tuned on GoEmotions \cite{demszky2020goemotions} (\texttt{SamLowe/roberta-base-go\_emotions}, about 125 million parameters). It returns 28 probabilities, which are summed into the seven families by the grouping the dataset's authors proposed (Appendix~\ref{app:instruments}), normalised to a distribution, and the three highest kept. A prompt is called emotional when its top-1 family is not neutral; \nEmotional{} of the \nAnalysed{} analysed prompts are, and \nNonEmotional{} are labelled neutral. That label is the reader's judgement and was never human-checked, which is why the neutral-labelled prompts are analysed as a group rather than discarded, and why Section~\ref{sec:method-analyses} audits them.

Two alternatives were tried on the prompt side and rejected with evidence. Zero-shot entailment with the same NLI model used on the image side over-read surprise on short text: a third of prompts came back with surprise as the top family, an artefact of the hypothesis wording on two-word inputs. A hand-built lexicon, the rule used in the first version of the pipeline, was transparent but brittle and could not represent a blended prompt. GoEmotions was retained because its training data are first-person social text, the register closest to a visitor's entry, and because re-extracting the prompt emotions with it left every headline result intact while removing the surprise artefact.

\subsection{Describer}

The describer is BLIP-VQA \cite{li2022blip} (\texttt{Salesforce/blip-vqa-base}, about 385 million parameters). It answers the five fixed questions in Appendix~\ref{app:instruments}, in order: the facial expression, what the person is doing, the body posture, how many people there are, and what is in the picture. The word ``emotion'' appears in none of them. Answers are cached per record, which is what allows the template ablation to re-run the extraction stage without re-running the vision model.

The describer was the third choice, not the first. A 3-billion-parameter vision--language model was the intended describer and was abandoned after it exhausted the 16~GB of memory on the machine available to me, thrashing into swap for 4~h~45~min with no completed record. A plain caption from BLIP's captioning head was too terse: read for emotion, it collapsed almost every drawing to a single family. BLIP-VQA's expression answer gives the downstream reader a cue that a caption does not, and the run over all \nTotal{} images completed at between one and twelve seconds a record. That its expression answer does most of the work is the central finding of the audits, and it is stated as such in Chapter~\ref{ch:results} rather than hidden in the method.

\subsection{Description template and image reader}

The five answers are composed into one sentence by the template in Appendix~\ref{app:instruments}: a drawing of so many people showing such a scene, the person doing this and holding that posture, the facial expression being whatever the describer said. BART fine-tuned on MultiNLI \cite{lewis2020bart, williams2018broad} (\texttt{facebook/bart-large-mnli}, about 407 million parameters) then scores each family as a hypothesis, ``This scene conveys \{family\}'', by entailment \cite{yin2019benchmarking}, and the three highest scores are kept.

The template has a property that must be said plainly here because everything in Sections~\ref{sec:results-describer} and \ref{sec:results-ablation} turns on it. It asserts a person and a facial expression for every drawing, including those in which the describer has just reported that there are no people. It was written that way in the first week of the build and its consequence was not measured until the audits in September. One alternative to the reader was tried and rejected: GoEmotions itself applied to the descriptions collapsed to neutral with probability above 0.95, because it needs first-person feeling words and a description has none.

\subsection{Face and scene classes}

My supervisor's expectation, from the perception literature, was that drawings with a face would be read more reliably than drawings of scenes. A record is face-classified when the describer reports at least one person and its expression answer contains a word from the documented list in Appendix~\ref{app:instruments}, matched by token so that ``man is smiling'' counts; every other record is scene-classified. The people count is parsed from digits and number words. Over all analysed records \nFaceAll{} are face-classified and \nSceneAll{} scene-classified; within the emotional prompts the split is \nFaceEmo{} to \nSceneEmo{}. The class is defined from the same description the image reader reads, and so the face/scene contrast is partly circular by construction. The circularity is stated now, quantified in Chapter~\ref{ch:results}, and addressed by the single-coder check, which classifies a sample of drawings without reference to the describer at all.

\section{The similarity ladder}
\label{sec:method-measures}

Let each reader return a top-3 list $T = \{(\ell_i, s_i)\}_{i=1}^{3}$ of families $\ell_i \in \mathcal{F}$ with scores $s_i$, where $\mathcal{F} = \{\text{joy}, \text{sadness}, \text{anger}, \text{fear}, \text{surprise}, \text{disgust}, \text{neutral}\}$. Write $P$ for the prompt reader's list and $Q$ for the image reader's, and $\operatorname{top}(T) = \ell_1$ for the top-1 family. Each family has a fixed centroid $c_\ell = (v_\ell, a_\ell)$ on the valence--arousal circumplex (Appendix~\ref{app:instruments}), hand-placed from the standard positions of the basic emotions \cite{russell1980circumplex}; per-family means from the NRC valence--arousal norms \cite{mohammad2018obtaining} are the documented alternative and a further-work item. The four measures below are ordered from loosest to strictest, and each rewards something the others ignore.

\paragraph{Valence--arousal similarity.} The score-weighted centroid of a reading and the similarity between two readings are
\begin{equation}
\mathbf{v}(T) = \frac{\sum_i s_i\, c_{\ell_i}}{\sum_i s_i}, \qquad
S_{\mathrm{VA}}(P, Q) = 1 - \frac{1}{\sqrt{2}}\,\Bigl\|\Bigl(\tfrac{v_P + 1}{2} - \tfrac{v_Q + 1}{2},\; a_P - a_Q\Bigr)\Bigr\|_2 ,
\label{eq:va}
\end{equation}
where $(v_P, a_P) = \mathbf{v}(P)$ and likewise for $Q$. Valence is rescaled to $[0,1]$ so both axes have unit range. This is the measure that gives partial credit to a near miss: a prompt read as joy and a drawing read as surprise are close on the plane, and the measure says so. It is also the measure that cannot fall to zero. Over the seven centroids the smallest attainable value is $0.412$ (joy against sadness), and randomly paired records average about \FullNeuVaNull{}; this floor is why the measure is never quoted without its null.

\paragraph{Top-3 soft overlap.} Each side is first normalised to a distribution over its own three families, $\tilde{p}_\ell = s_\ell / \sum_j s_j$, so the prompt reader's multi-label scale and the image reader's softmax scale are comparable; the overlap is the sum of per-family minima,
\begin{equation}
S_{\mathrm{ovl}}(P, Q) = \sum_{\ell \in \mathcal{F}} \min\bigl(\tilde{p}_\ell,\; \tilde{q}_\ell\bigr) \in [0, 1],
\label{eq:overlap}
\end{equation}
which equals one only when the two distributions coincide. It rewards a second or third choice that the other reader also made, and it is the only measure that uses the scores rather than just the labels.

\paragraph{Family agreement.} Over a set of $n$ records,
\begin{equation}
A_{\mathrm{fam}} = \frac{1}{n} \sum_{i=1}^{n} \mathbb{1}\bigl[\operatorname{top}(P_i) = \operatorname{top}(Q_i)\bigr].
\label{eq:family}
\end{equation}
This is the strictest rung and the one most comparable with other studies; it is also the one whose chance level depends most on the family marginals, since a reader that says joy often will agree with a prompt reader that says joy often.

\paragraph{Valence-sign agreement.} With $\sigma(\ell) \in \{+, -, 0\}$ the sign of a family ($+$ for joy; $-$ for sadness, anger, fear, disgust; $0$ for surprise and neutral),
\begin{equation}
A_{\mathrm{sign}} = \frac{\sum_{i} \mathbb{1}\bigl[\sigma(\operatorname{top} P_i) \neq 0 \;\wedge\; \sigma(\operatorname{top} P_i) = \sigma(\operatorname{top} Q_i)\bigr]}{\sum_{i} \mathbb{1}\bigl[\sigma(\operatorname{top} P_i) \neq 0\bigr]} ,
\label{eq:sign}
\end{equation}
so records whose prompt family has no sign are excluded from the denominator; the denominator is reported with every value (for example \FullEmoNSign{} of the \FullEmoN{} emotional prompts). It asks the coarsest categorical question, whether the two readers landed on the same side of neutral, and it is the rung on which the headline result rests.

\section{The random-pairing null}
\label{sec:method-null}

The measures do not start at zero. Equation~\ref{eq:va} has a floor, and the family marginals in Table~\ref{tab:families} make agreement on joy likely by chance alone. The null adopted is the exchangeability hypothesis that the image reading is unrelated to the prompt \cite{good2005permutation}: if that were true, re-pairing the drawings with the wrong prompts would change nothing on average. For a subset of $n$ records and a measure $m$, draw $K$ random permutations $\pi_k$ of the image readings and compute $m_k = m\bigl(\{(P_i, Q_{\pi_k(i)})\}_{i=1}^{n}\bigr)$. With $\hat\mu = \frac{1}{K}\sum_k m_k$ and $\hat\sigma$ the standard deviation of $\{m_k\}$,
\begin{equation}
z = \frac{m_{\mathrm{obs}} - \hat\mu}{\hat\sigma}, \qquad K = \nullShuffles,\ \text{seed}\ \nullSeed .
\label{eq:z}
\end{equation}
Two cautions attach to $z$. With $K = \nullShuffles{}$ re-pairings, $\hat\sigma$ is itself an estimate; across seeds 1 to 5 the headline $z$ moves between \ZSeedMin{} and \ZSeedMax{} while the null mean stays within a tenth of a point, so $z$ orders effects and should not be read as a precise probability. And a null can be \emph{degenerate}: when $\hat\sigma = 0$, which happens for family agreement when every prompt in the subset shares one top-1 family and for valence-sign agreement when every prompt shares one sign, permuting the image side cannot change the score and there is nothing to test. The analysis detects this from the null itself and prints no $z$ for such cells. An earlier version flagged degeneracy by hand for two subsets and missed a third; detecting it from the null's spread removed the judgement.

\section{Inference}
\label{sec:method-inference}

Records are not independent. \nRepeats{} of them repeat an earlier prompt, and the drawings of one prompt share whatever that prompt does to the readers. Every interval and every test below therefore treats the prompt group as the unit \cite{cameron2008bootstrap}.

\paragraph{Clustered bootstrap confidence intervals.} Let $\mathcal{G}$ be the set of prompt groups in a subset. For $b = 1, \dots, B$ draw $|\mathcal{G}|$ groups with replacement, pool their records, and recompute the measure; the 95\% interval is the 2.5th and 97.5th percentiles of the $B$ values \cite{efron1993introduction}, with $B = \DiffDraws$ and seed \nullSeed.

\paragraph{Clustered permutation test of the face/scene difference.} Under the null that the image class is unrelated to agreement, the face/scene labels are exchangeable across prompt groups. The labels are permuted across groups $P$ times and the difference in agreement recomputed; the two-sided $p$-value uses the estimator of \cite{north2002note},
\begin{equation}
p = \frac{k + 1}{P + 1}, \qquad k = \#\{\text{permuted differences at least as extreme as the observed}\},
\label{eq:permp}
\end{equation}
so the smallest reportable value with $P = \DiffDraws$ is $10^{-4}$.

\paragraph{Cohen's kappa.} For comparability with other studies, family agreement is also reported as
\begin{equation}
\kappa = \frac{p_o - p_e}{1 - p_e},
\label{eq:kappa}
\end{equation}
with $p_o$ the observed top-1 agreement and $p_e$ the agreement expected from the two readers' family marginals \cite{cohen1960coefficient}, interpreted with the bands of \cite{landis1977measurement}; intervals by the clustered bootstrap above.

\paragraph{Multiple comparisons.} The analysis prints \HolmM{} non-degenerate $z$-scores. Each is converted to a two-sided $p$ by the normal approximation and the family is controlled with the Holm--Bonferroni step-down procedure \cite{holm1979simple}: order $p_{(1)} \le \dots \le p_{(m)}$ and reject while $p_{(i)} \le \alpha / (m - i + 1)$, $\alpha = 0.05$. The normal approximation is nominal for the largest $z$; it affects none of the decisions, which turn on the cells near the threshold.

\paragraph{Paired comparison of two image readers.} On the same records each reader either agrees with the prompt reader or does not. With $b$ the records only the first reader agrees on and $c$ only the second, McNemar's exact binomial test \cite{mcnemar1947note} on $(b, c)$ treats records as independent and is therefore optimistic here; the clustered version flips the sign of each prompt group's summed difference as a block (\McClusterDraws{} draws) and the clustered bootstrap gives the interval on the difference in rates.

\paragraph{Wilson intervals.} Proportions from the single-coder check use the Wilson score interval \cite{wilson1927probable}, which behaves at small $n$ and near 0 and 1.

\section{Analyses}
\label{sec:method-analyses}

The analyses are listed in the order Chapter~\ref{ch:results} reports them; each is one script, and each writes a JSON file from which the tables, the figures and the numbers in this document are generated.

\paragraph{Splits and the main table.} \texttt{analysis\_final.py} computes the four measures and their nulls on the emotional prompts, on the face- and scene-classified records within them, on the positive- and negative-valence prompts (where only the valence--arousal measure has a live null), and on the neutral-labelled prompts, all against Equation~\ref{eq:z}. The same table is recomputed on the first occurrence of each prompt, \nDistinct{} records, as the robustness check against repetition.

\paragraph{The face/scene difference.} \texttt{significance.py} computes the clustered bootstrap interval on the difference and the clustered permutation test above, for valence-sign and family agreement. \texttt{inference.py} adds the clustered intervals for every subset and measure, Cohen's kappa, the Holm procedure over every printed $z$, and the seed sensitivity of the headline $z$.

\paragraph{Specificity check.} Prompts the text reader labels neutral should show no agreement above their null. Only the valence--arousal measure is informative there, since the other three are degenerate on a subset whose every prompt shares one label.

\paragraph{Method comparison.} \texttt{method\_comparison.py} holds the prompt reader, the subset, the four measures and the random re-pairings fixed and varies only the image reader: describe-then-extract against a direct CLIP zero-shot reader \cite{radford2021learning, ilharco2021openclip} (ViT-B/32, LAION-2B weights) prompted with the seven families, its output frozen in a results file so the main pipeline cannot overwrite it. The paired tests are those of Section~\ref{sec:method-inference}. An earlier comparison from the first build used a different prompt reader, a different subset and a different overlap formula; it is kept as a record in Table~\ref{tab:methodvone} and is not comparable with the main analysis.

\paragraph{Consistency across repeated prompts.} For a prompt group $g$ with $n_g \ge 2$ records and image top-1 families $\{\operatorname{top}(Q_i)\}_{i \in g}$, the modal fraction is $c_g = \max_{\ell} n_{g,\ell} / n_g$, and the consistency is the mean $C = \frac{1}{|\mathcal{G}_{\ge 2}|} \sum_g c_g$ over the \nGroups{} groups. Because \nPairGroups{} groups are pairs, $c_g$ cannot fall below $0.5$ for them, so $C$ is read against a permutation null that shuffles the image top-1 families across all \nAnalysed{} analysed records and re-cuts them into the same groups (\ConsDraws{} draws). The count of fully consistent groups ($c_g = 1$) is treated the same way. This bounds the reproducibility of the whole prompt-to-reading chain; it does not isolate the generator, whose parameters were not recorded, and it cannot separate a visitor who typed ``happy'' twice from two visitors who typed it once each.

\paragraph{Control audit.} \texttt{audits.py} runs a fixed lexicon of \CtrlLexicon{} plain English affect words over the \CtrlN{} neutral-labelled prompts, identifies the two records that reduce to the placeholder, and re-runs the specificity check on the cleaned control with both sets removed.

\paragraph{Describer audit and copy rate.} The same script crosses the describer's people count with the presence of an expression word, counts the smile answers, and computes the copy rate. Where the describer's expression answer is a single word that names an emotion (strict: happy, sad, angry, \dots; \DescBareStrictN{} records) or a facial action with an implied family (broad: smile, crying, \dots; \DescBareBroadN{} records), the copy rate is the share of those records in which the image reader's top-1 family equals the family the word implies. It measures how much the ``separate'' extraction stage adds beyond the describer's own word.

\paragraph{Error taxonomy.} \texttt{error\_taxonomy.py} selects every emotional record on which both readers scored their top-1 family at 0.8 or above and disagreed, tags each automatically (people count, bare expression word, mixed-feeling connective, ambiguous raw label, short prompt), and then, for each, I looked at the drawing and assigned one primary failure mode from a fixed set of six: the describer invented a face or expression; the describer misread one; the reader mis-inferred from a correct description; the prompt was ambiguous or mixed; the drawing does not depict the prompt; the prompt reader was wrong. The tie-break rule is written in the script's output.

\paragraph{Template ablation.} \texttt{ablate\_nli.py} rebuilds each record's description from its cached answers under an altered template, re-runs only the entailment stage, and recomputes the ladder and its nulls with the same code and seed. The variants drop one clause at a time (expression, action, posture, people count, scene), fix the expression word to ``unclear'' for every record, and, in two people-aware variants, omit the person and expression clauses wherever the describer reported no people. A control variant re-runs the unmodified template under the same conditions, so numerical noise can be separated from template effects.

\paragraph{Single-coder check.} \texttt{human\_check.py} draws a fixed sample of 120 drawings stratified on the describer's output (face-classified, scene-classified with no people reported, and every record with a vague or word-only people answer), lays them out as numbered contact sheets that show nothing but the drawings, and, once coded, scores the describer's people count and expression answer and the image reader's valence against the coder with Wilson intervals, then re-runs the face/scene contrast on the coder's split. The coder works blind to the prompt, the description and both readings. Figure~\ref{fig:codingsheet} shows one sheet.

\section{The demonstrator}
\label{sec:method-demo}

The pipeline is exposed as a small local web application (\texttt{app.py}) that runs the real models on any of the \nAnalysed{} records or on an uploaded image, shows the five answers and the composed description, the two readings side by side, and the four measures against the same null the analysis uses, computed at start-up from the same result files. Three design choices carry the methodology into the interface. The valence--arousal axis starts at its floor rather than at zero and shades the middle half of random pairings, so a value that is below chance looks below chance. The verdict leads with valence-sign and family agreement and reports the loosest measure as a percentile of random pairings. And where a chance level is degenerate the interface says so rather than printing one. Nothing a visitor types or uploads is stored, and the request log is suppressed. It was built as a testing and communication tool, used in the supervision meetings and the project presentation, and it is not a data-collection instrument.

\section{Reproducibility and testing}
\label{sec:method-repro}

The environment is pinned (\texttt{requirements.txt}; Python 3.12, PyTorch 2.13, Transformers 5.14), every random process is seeded, and every model output is cached per record, so that every analysis after the pipeline itself re-runs in seconds. The direct-CLIP baseline is a frozen file. One module, \texttt{emoviz/metrics.py}, holds the only definition of every constant, measure, split rule and the null, and every script imports it; before it existed two scripts carried two slightly different overlap formulas, and the difference, though negligible on this data, was exactly the kind of drift the module now prevents.

Testing has two layers. \texttt{test.sh} runs 38 smoke checks: the environment, the integrity of the corpus and the cached outputs, the redaction audit, every analysis script to a clean exit, a live three-image run of the pipeline on fresh images, and the figure build. \texttt{test\_numeric.py} pins 54 values: every headline number in this document is asserted against the JSON file that produces it within a stated tolerance, and the measures themselves are unit-tested (the 0.412 floor, symmetry, the bounds and scale invariance of the overlap, the sign map, the face rule). A change in the analysis fails the build rather than drifting into the text. The figures (\texttt{make\_figures.py}) and every table and number in this dissertation (\texttt{export\_tex.py}) are generated from the same files, which is why no result number is typed by hand anywhere in the document.

What the tests do not do should be stated as plainly. None of them validates a model answer against a human judgement. The pipeline's completion figure, all \nTotal{} images processed with no unhandled error, is a robustness statement and not a correctness one; the single-coder check is the only place a person enters the chain. Appendix~\ref{app:repro} lists the files and the run order.
